# Public synthetic FinTS byte-syntax fixtures

`syntax-v1.json` contains six independently generated byte sequences and their
expected headers, positional fields, scalar kinds and decoded bytes. Wire data
uses base64 and scalar values use hex to make binary/control characters safe
to inspect. All examples are synthetic; none is a bank capture.

| Vector | Coverage |
| --- | --- |
| empty-structural-frame | Byte size, outer versions and matching message numbers |
| escaped-text-and-omissions | Five syntax escapes, absent/trailing fields and components, optional segment reference |
| binary-octets | All 256 octets, delimiter isolation and empty binary |
| response-reference-and-unknown-segment | Message reference, unknown version, non-ASCII and CR/LF bytes preserved without charset guessing |
| opaque-security-wrapper | Reserved outer numbering and an opaque binary payload |
| binary-component-and-empty-positions | Binary within a group, adjacent empty components and trailing omissions |

Regenerate from the repository root with
`python eng/Generate-FinTsVectors.py`. The optional producer uses Python's
standard library and no .NET code. Normal tests use the committed embedded
fixture and need no Python, PDF, network or bank service. Regeneration must
produce byte-identical fixture content.

Run `dotnet run --project tests/Broiler.Fond.Kernel.Tests`, or
`./eng/Invoke-CI.ps1 -Scope Full` for the full Windows checks.
`FinTsSyntaxTests` also verifies every frame prefix, malformed headers and
binary prefixes, data isolation, deterministic generated bytes, safe errors,
culture independence and fixed resource boundaries.

The empty structural frame and dummy wrapper are deliberately **not valid
banking dialogues or security-profile fixtures**. No fixture certifies BPD/UPD,
PIN/TAN, signatures, balance schemas, a bank or a supported operation. The
workflow simulator remains separate from this byte layer until typed segment
schemas can bridge them. Never substitute real account or credential data.

Reference details and exact scope: [ADR 0010](../../../../docs/adr/0010-fints-byte-syntax-and-framing.md).

## Typed response fixtures

`responses-v1.json` adds five independent response cases generated by the same
Python command: receipt, pending authorization/pagination, indeterminate
processing, an unknown code/body segment, and contradictory status. Expected
meanings are explicitly selected in the producer, separate from the .NET code.
Raw fields are compared byte-for-byte by `FinTsResponseTests`.

The response suite also checks schema limits, malformed/reference errors,
concurrent callers, per-instance replay protection, terminal stop and every
counter value through 9999. These are unwrapped synthetic schema frames;
they do not authenticate a bank or qualify a security procedure. The
correlation tracker sends nothing, and a match is not a completion result.
See [ADR 0011](../../../../docs/adr/0011-fints-responses-and-dialogue-correlation.md).

## Parameter fixtures

`parameters-v1.json` adds five synthetic BPD/UPD cases: general bank and listed
operations, unlisted-blocked policy, missing user scope, duplicate evidence,
and no accounts with an opaque endpoint segment. The existing Python generator
regenerates all three fixture files; .NET tests consume the embedded JSON.
They assert independently selected account/policy expectations and exact wire
retention. Additional tests cover typed fields, limits, cardinalities, omitted
sections and canonical extension positioning.

No account is allocated and no endpoint or parameter cache is updated. These
are parameter-evidence fixtures, not proof that an institution, user or operation
is authenticated or supported. [ADR 0012](../../../../docs/adr/0012-fints-parameter-evidence.md)
records supported versions, bounds and deliberately unsupported layouts.

## PIN/TAN envelope and parameter fixtures

`pin-tan-v1.json` adds five independent response wrappers: PIN:1 with J,
PIN:2 with N and explicit zero bounds, omitted bounds with an unlisted
operation, duplicate conflicting operation flags, and an unknown HIPINS
version alongside known evidence. Each includes an opaque binary field
containing all 256 byte values inside the plaintext body. Expected profile,

The .NET suite adds malformed and nested-wrapper rejection, exact combined

contains actual credentials, verifies authentication or qualifies a bank.
Reported N flags cannot establish SCA exemption. The local HIPINS limit is
125 operation pairs, below the protocol's 999 because of the syntax budget.
See [ADR 0014](../../../../docs/adr/0014-pin-tan-envelope-and-parameters.md).
